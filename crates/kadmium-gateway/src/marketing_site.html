02 / From machine to task

Inspect. Configure. Run.

  1. Inspect your hardware.

    Start the coordinator and open Control Room on the host machine. Review hardware and reachable workers before choosing a workload.

  2. Choose your model.

    Prepare a supported local checkpoint with a separately installed Ollama backend, or configure your hosted provider. Review the destination before sending data.

  3. Open Condenser.

    Launch it from Models in Control Room or Companion. Choose the task’s provider and model, then work in your local workspace. Provider charges, if any, are separate.

From a source checkout
git clone https://github.com/mESmaC/Kadmium.git
cd Kadmium
cargo run --locked -p kadmium-cli -- probe
cargo run --locked -p kadmium-cli -- serve --port 7848

Install Rust via rustup first; the repository selects its pinned toolchain. Then open http://127.0.0.1:7848 on the host machine, not on this website.

The gateway’s /v1 model routes return diagnostics. For generation, follow the local checkpoint guide or configure a provider in Condenser. Native multi-device model execution remains development work.

04 / The model-quality contract

Keep the model
you chose.

Speed and memory pressure are not permission to lower model quality. The website follows the local product’s contract, not a separate cloud quality tier.

Read the quality settings ↗

  • Maximum means maximum

    Use the model and backend’s supported context and output maximums, not a guessed token cap. Leave quality overrides blank for maximum; missing required provider metadata needs an explicit error.

  • No hidden shortcuts

    Do not silently truncate prompts, compact history, quantize weights or switch models or backends to make a request fit. A failure must stay visible to you.

  • Your limits, your decision

    If you choose a lower limit, the control must state what you lose. Input beyond your chosen window is rejected, not truncated; a chosen output limit stops responses. Reset to maximum clears your overrides.

05 / Kadmium Cloud · Roadmap

An optional extension.
Not a different product.

The target is managed capacity alongside your local setup, not a replacement for self-hosting or a reason to reduce model quality. These capabilities are planned or simulated today, not services you can purchase.

Read the current cloud boundaries ↗

  • Burst capacity PLANNED

    Rented compute for workloads that need more room. Live procurement, billing and spend enforcement must be established before a managed offering.

  • CloudShield SIMULATED

    A future failover path when local capacity goes away. Current scenarios do not establish production continuity or a failover guarantee.

  • Supply Grid hosting PLANNED

    A proposed market for permitted spare compute. Paid leases and host payouts are not live; there is no earnings estimate or income guarantee.

06 / Before you begin

A few things to know.

What can I run today?

The project includes a local control plane, planners, TCP workers and reference workloads. Condenser can run tasks through configured providers and use supported local checkpoints through Ollama. Production native multi-device model serving is still integration work. See the API contract for execution boundaries.

Can I run my local workspace on this website?

No. Run Control Room, Companion and Condenser on your own machine. This website does not connect to your local coordinator, read your files, or provide a hosted inference session. Use the access link printed by your coordinator or open Condenser from your local app.

Is a hosted provider the same as Kadmium Cloud?

No. A provider you configure in Condenser is a separate service with its own endpoint, account and charges. Kadmium Cloud’s managed capacity, failover and host marketplace remain planned or simulated. Self-hosting does not require a Kadmium cloud subscription.

What would I be paying Kadmium for?

Paid setup pilots and ongoing support are proposals, not generally available plans or a checkout. Scope, acceptance criteria, terms and support capacity must be agreed before work starts. Compute, provider charges and hardware are separate. See the commercial proposal for context.

Does self-hosting keep all my data local?

That depends on the provider and endpoints you configure. A remote provider receives the data sent to it. Review the full data route, model rights and machine permissions before use; self-hosting alone is not a zero-egress or compliance guarantee.

Can I earn money by hosting a node?

There is no live paid Supply Grid in this repository. Local workers can participate in supported compute workflows, but adding a machine does not create a paid lease or payout. Any future host offering will need terms that account for power, networking, availability and demand.

Is this ready for production-critical or regulated workloads?

Those workloads are outside the proposed first pilot. Start with a non-sensitive evaluation and a named technical owner. Production SLAs and regulated deployments require separately demonstrated controls, support and contracts.
