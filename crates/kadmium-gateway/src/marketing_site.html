02 / A bounded first step

A useful result before a bigger commitment.

  1. Bring the real constraint.

    Choose a recurring task, identify permitted hardware, and agree on a quality bar. Start with public or synthetic data and a baseline from your existing workflow.

  2. Build a repeatable setup.

    Evaluate one supported configuration. Record the model provider, data route, operator steps, costs and limits so the result can be checked.

  3. Make an informed call.

    Leave with a report, a runbook and a go/no-go recommendation. The right outcome may be a simpler tool, a different machine, or no further work.

03 / Your hardware, your operation

Start local.
Keep the setup in your hands.

Build from source and explore the Control Room. For model answers, use Condenser with a configured provider, including a separately installed local Ollama backend.

  • Inspect hardware and plan work across reachable machines.
  • Normalize supported GGUF or SafeTensors checkpoints while preserving their source bytes.
  • Explicitly load a supported checkpoint in Ollama and choose it for your task.
Read the setup guideBrowse the source ↗

You provide hardware, power, storage and administration. Model compatibility and backend support vary; check the guides for your configuration.

From a source checkout
git clone https://github.com/mESmaC/Kadmium.git
cd Kadmium
cargo run --locked -p kadmium-cli -- probe
cargo run --locked -p kadmium-cli -- serve --port 7848

Install Rust via rustup first; the repository selects its pinned toolchain. Then open http://127.0.0.1:7848 on the host machine.

The gateway’s /v1 model routes return diagnostics. For generation, follow the local checkpoint guide or configure a provider in Condenser. Native multi-device model execution remains development work.

05 / Before you begin

A few things to know.

What can I run today?

The project includes a local control plane, planners, TCP workers and reference workloads. Condenser can run tasks through configured providers and use supported local checkpoints through Ollama. Production native multi-device model serving is still integration work. See the API contract for execution boundaries.

What would I be paying Kadmium for?

The proposed pilot pays for agreed setup and evaluation deliverables: one workload, a reproducibility report and a runbook. Proposed ongoing support covers an approved deployment within a defined scope. Neither includes rented compute, provider credits or unlimited support. Availability and terms must be agreed before work starts.

Does self-hosting keep all my data local?

That depends on the provider and endpoints you configure. A remote provider receives the data sent to it. Review the full data route, model rights and machine permissions before use; self-hosting alone is not a zero-egress or compliance guarantee.

Can I earn money by hosting a node?

There is no live paid Supply Grid in this repository. Local workers can participate in supported compute workflows, but adding a machine does not create a paid lease or payout. Any future host offering will need terms that account for power, networking, availability and demand.

Is this ready for production-critical or regulated workloads?

Those workloads are outside the proposed first pilot. Start with a non-sensitive evaluation and a named technical owner. Production SLAs and regulated deployments require separately demonstrated controls, support and contracts.
