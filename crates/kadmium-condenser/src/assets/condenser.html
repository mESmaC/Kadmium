Prepare a model for Condenser

LOSSLESS

Preserve the model you chose. Normalize its storage, load it in local Ollama, then use it for coding, research, questions, math, or science.

Choose a GGUF v3 file or a complete model directory. SafeTensors needs config and tokenizer files; split checkpoints need every shard. Normalization keeps originals and writes an additional copy in KTB banks.

No precision conversion, expert removal, or layer skipping.

Model library: Loading…. Each package contains manifest.json, source/ originals, and banks/ normalized .ktb shards. Allow at least twice the source size, plus the backend's copy.

Start Ollama first. Loading uses the preserved source files, checks tensor metadata, and keeps the checkpoint's declared context size. If it cannot load at that size and precision, it reports the failure.

Tradeoff: a smaller window lowers KV-cache memory and prefill time, but the model can attend to less prompt, history and output at once, and long-context recall and reasoning degrade.

KTB is a storage format. Generation runs in Ollama; backend arithmetic is not RepOps-certified.

Use a different hostname on each worker. Resource offers and polite-state limits still apply. These listeners are for a trusted network, not a public internet deployment.

Provider settings

    

      

      

      

      

      
Memory-only. Never written to task history.

      

      
      

        Quality & token limits
        
Blank means maximum: full model input/context and maximum output. Input and output share the model's context window. Original precision is preserved; no automatic history pruning. If an OpenAI-compatible server does not advertise an output maximum, Condenser omits the limit so the server's own maximum applies. Anthropic requires a value; enter its documented limit if it is not reported.

        

          

          

          

          

        

          
For other providers, context is configured on the server. Condenser sends all input; backend limits still apply. Lower limits only when you choose to. Temperature controls randomness, not model precision.

          
    
            
  • Output tokens: a lower value caps generation length and can truncate multi-step reasoning or long code and answers mid-response.
    • 
            
  • Context / input window: a lower value reduces KV memory and prefill time, but shrinks total input + output capacity and degrades long-range recall.
    • 
            
  • Request timeout: a short timeout bounds waiting, but can abort deep reasoning or large-context prefill before the turn completes.
    • 
          

          
Run budgets can also leave work incomplete. Memory retrieval adds evidence without shrinking the conversation.

        
        

      

      

        DeepSeek-V4.1 & MCL4-COE controls
        
        
Tradeoff: uses fewer tokens per turn, but strips earlier reasoning traces and truncates older tool outputs that later turns may rely on.
