Kadmium ([kadmium.ai](https://kadmium.ai), written `kadmium` in code, `Cd‑48` as its signature) is a Rust compute-fabric project for planning and reference workloads across heterogeneous machines. Current model-related execution uses small synthetic tensors; production model serving and distributed large-model training remain integration work. Kadmium Cloud is the **planned** managed plane for burst GPUs, spot arbitrage, and failover; those services are not established as live offerings by this repository.

The identity comes from the name. In a reactor, cadmium control rods are inserted to different depths to regulate the reaction; in Kadmium, shards are placed on heterogeneous nodes in different proportions. **The mark is a head plate with four rods inserted to unequal depths**, drawn in cadmium yellow — the pigment the element is famous for — on cool graphite. Everything else follows from that: the rod lattice is the one pattern, the shard rail is the one chart, yellow means *local*, and a second colour, Cherenkov blue, is reserved for anything that runs in the cloud.

## Principles

- **Instrument, not advertisement.** Kadmium is a control room. Surfaces are graphite, type is quiet, numbers are mono, and the only saturated colour on a screen is doing a job. If a screen has more than one cadmium element competing for attention, one of them is wrong.
- **Yellow is local, blue is cloud. Always.** `cadmium` paints hardware the person owns and the open-source product; `cherenkov` paints rented, managed or remote compute and the Cloud product. Never swap them, never use either as decoration, never introduce a third accent.
- **Dark is home.** Dark is the primary theme — the dashboard, the docs, the site. The light theme exists for printed and embedded contexts; every token holds its contrast there too, but design in dark first.
- **Rods, not charts.** When something is distributed across nodes, draw it as rods hanging from a rail (`ShardRail`) before reaching for a pie or a stacked bar. When something is a level, draw a `Meter`. Depth and length carry the quantity; the label carries the name.
- **Say the hardware.** Copy names real machines, real models and real numbers with units — "M4 Mac Mini, 64 GB unified", "deepseek-v3-671b", "2.3 Gbps" — and never "powerful", "seamless" or "blazing".

## Using this system

**Themes.** `tokens.json` carries two themes, `dark` first (the fallback) and `light`. Set `data-theme="dark"` or `data-theme="light"` on `<html>`; the compiled `tokens.css` declares every colour and shadow per theme and every spacing, radius, size and font variable once.

**Colour.** Build on the four graphite surfaces (`graphite-0` page → `graphite-3` pressed) with `line` hairlines and `line-strong` control borders. Text is `ink`, `ink-muted` or — for placeholders only — `ink-faint`. Paint a primary action `cadmium` with `on-cadmium` text and a `cadmium-edge` border; write cadmium as text with `cadmium-text` (in light it is a dark gold, never the fill yellow). Do the same for the cloud: `cherenkov`, `on-cherenkov`, `cherenkov-text`, `cherenkov-soft`. Status is `ok` (a teal, so it is never confused with danger by hue), `warn` (orange — always beside a word or the alert icon, because it sits near cadmium) and `danger`, each with a `-soft` ground. Memory tiers are `tier-hot`, `tier-warm`, `tier-cold`: one yellow at three lightnesses. Every text token's usage note names the grounds it holds 4.5:1 on in both themes; keep to those pairs.

**Type.** Two families, both included as files: Archivo (`sans`) for everything a person reads, JetBrains Mono (`mono`) for everything a person copies, compares or counts. Use the styles, not raw sizes: `display-xl` and `display` for hero and page titles, `headline` and `title` for sections and cards, `body` for prose (never smaller than `caption`), `label` uppercase for eyebrows, badges and meter labels, `metric` for the big number, `code` and `code-sm` for commands, hostnames, shard ranges and hardware lines. There is no italic in the system; emphasize with `body-strong` or by switching to mono.

**Space, shape, depth.** A 4px grid: `space-1` … `space-16`. Cards pad `space-4`; sections sit `space-6` apart — the rod pitch. Corners are `radius-sm` on controls, `radius-md` on cards and code, `radius-lg` on dialogs, `radius-tile` (22 %) on app tiles, `radius-full` only on badges, dots and rods. Elevation is mostly a `line` border plus `shadow-sm`; floating surfaces take `shadow-lg`, which already includes the hairline. Keyboard focus is the `focus-ring` shadow on `:focus-visible`: a 2px gap in the page colour, then 2px of solid `cadmium-text`.

**Marks and icons.** The mark, wordmark, tiles and favicon are in `assets/Logos` (SVG, dark- and light-ground versions; read `assets/Logos/README.md` for clear space and don'ts). Icons are 24px, 1.75px stroke, round caps — the twelve Kadmium-specific glyphs live in `assets/Icons`; for everything else use Lucide at the same stroke, as `4-marks-and-iconography.md` explains.

**Glass.** `glass.css` is the shared material layer for Kadmium and Condenser. Load it after `tokens.css` for translucent surfaces (`.k-glass`), native system type, generous radii, segmented controls (`.k-segmented`), steppers (`.k-steps`), pills (`.k-pill`) and progress bars (`.k-progress`). Opaque fallbacks apply without `backdrop-filter`, and reduced-transparency and reduced-motion preferences are honoured.

**Components.** `components/bundle.js` is one classic script that attaches `window.Kadmium` (`Button`, `Badge`, `Meter`, `NodeCard`, `ShardRail`, `PlanCard`, `CodeBlock`, `Input`, `Tabs`, `Mark`) and expects React 18 as `window.React` / `window.ReactDOM` (carried in `components/lib/`), with `tokens.css` and `components/bundle.css` on the page. Each component's `README.md` says what you provide and when to use it; `components/index.d.ts` documents the props.
